CHAPTER 01

计算机系统概述

低频 · 2-4 分
本章定位纯记忆型章节，几乎没有大题。集中考 2-3 道单选：冯诺依曼结构特征、性能指标计算（CPI / MIPS / CPU 时间）、存储容量与带宽的单位换算。花半天过一遍就够，别在这章耗时间。
考点清单

1. 冯·诺依曼结构 必考

  • 五大部件：运算器、控制器、存储器、输入设备、输出设备
  • 核心思想：存储程序——程序和数据一样，先存入主存，再按地址顺序自动取出执行
  • 指令和数据都以二进制形式存放，形式上无差别，靠执行阶段区分
  • 指令 = 操作码 + 地址码
  • 以运算器为中心 → 现代计算机改为以存储器为中心，且 CPU 与主存间加了 Cache

2. CPU = 运算器 + 控制器 必考

部件组成职责
运算器ALU + ACC / MQ / X + PSW数据加工：算术运算、逻辑运算
控制器PC + IR + CU指挥：取指令 → 分析指令 → 执行指令
  • ACC 累加器（存操作数/结果）、MQ 乘商寄存器（乘除专用）、X 通用操作数寄存器——前三个必须具备
  • PSW 标志寄存器：存放运算结果特征（ZF 零 / CF 进位 / OF 溢出 / SF 符号），条件转移要用它
  • PC：存下一条指令的地址，可自动 +1；与主存的 MAR 之间有一条直接通路
  • IR：存当前指令，内容来自 MDR；操作码送 CU 分析，地址码送 MAR
  • 辨析（高频）：PC、IR 属于控制器；ACC、MQ、X、PSW 属于运算器；MAR、MDR 现代机器也集成在 CPU 内，对用户透明
口径第一章只要求 PC / IR / CU 三件；第 5 章会把 CU 展开为「指令译码器 + 时序系统 + 微操作信号发生器」。两种说法都对——问「谁属于控制器」答 PC、IR、CU，问「控制器内部结构」再展开。

3. 层次结构

  • 硬件层 → 系统软件层 → 应用软件层
  • 系统软件：OS、编译程序、数据库管理系统（DBMS）
  • 数据库管理系统属于系统软件，不是应用软件（爱考）
  • 各层之间的界面由指令系统（ISA）连接：硬件与软件的分界面
  • ISA 是软硬件接口，属于软件可见的部分

4. 性能指标 计算

CPU 时间 = 指令条数 × CPI × 时钟周期 = 指令条数 × CPI ÷ 主频
MIPS = 主频 ÷ (CPI × 10⁶) = 指令条数 ÷ (执行时间 × 10⁶)
  • CPI = 程序总时钟周期数 ÷ 指令条数
  • 主频 f = 1 / 时钟周期 T
  • CPU 时间 = 用户 CPU 时间 + 系统 CPU 时间
  • MIPS 不能跨指令系统比较（不同 ISA 一条指令干的活不同）

5. 易混单位换算 坑点

量进制示例
存储容量2¹⁰1 KB = 1024 B
速率 / 带宽10³1 KB/s = 1000 B/s
频率10³1 GHz = 10⁹ Hz
易错容量用 2 的幂，传输速率用 10 的幂，二者混考是常见失分点。

蓝球 · 指令流　控制器把地址送上总线到存储器 → 存储器按这个地址把指令送回来。 （这一步叫「取指」）
橙球 · 数据流　运算器把地址送上总线到存储器 → 存储器把操作数送回来；算完之后，结果再沿原路写回去。 （这一步叫「取数」与「写回」）
灰色虚线　每个部件都挂在这同一条系统总线上 —— 同一时刻只允许一个部件往上送数据。
关键 盯住两个球看：它们走的是同一条总线、访问的是同一个存储器。 这不是画得偷懒，而是冯·诺依曼结构最核心的一点 —— 指令和数据在硬件层面没有任何区别，都是二进制、都存在主存里、都靠地址来定位。 CPU 之所以分得清谁是「指令」谁是「数据」，只是因为它在不同的时机、按不同的用途去取罢了。

自测速答

Q1 · 判断

CPU 可以直接访问硬盘上保存的指令。

答错。CPU 只能直接访问主存和寄存器，外存必须通过 I/O 先调入主存。

Q2 · 计算

主频 2 GHz，程序共 10⁸ 条指令，平均 CPI = 2.5，求 CPU 时间与 MIPS。

答CPU 时间 = 10⁸ × 2.5 ÷ 2×10⁹ = 0.125 s；MIPS = 2000 ÷ 2.5 = 800。
CHAPTER 02

数据的表示和运算

高频 · 8-11 分
本章定位「必考 + 易错」双标签。单选里补码、移码、溢出判断、海明码各占 1 题；大题常和第三章合考（如给出浮点格式求表示范围、手算浮点加减步骤）。核心心法：把每个二进制位当成有地址的格子，所有公式都从「位数」推出来，别死背。
跨科目本章的海明码与 CRC 在计网的帧校验里会再遇到；大小端问题在协议字段解析时也会用到。而位运算本身是数据结构里位图、哈希的基础。至于补码与浮点 —— 它们是后面所有章节的算术基础，这章不牢，存储和 CPU 都没法算。
考点清单

1. 四种机器数 必考

编码正数负数
原码符号 0 + 数值符号 1 + 数值
反码同原码数值位取反
补码同原码反码 + 1
移码补码的符号位取反
n 位补码范围：−2⁽ⁿ⁻¹⁾ ～ 2⁽ⁿ⁻¹⁾−1 3 位补码： 100 ~ 011 (−4 ~ +3)
  • 原码、反码的 0 有两种表示（±0）；补码、移码的 0 唯一
  • 移码只用于浮点数的阶码，好处是能直接按无符号数比较大小
  • 负数补码 → 原码：符号位不动，其余取反加 1（和原码转补码同一套操作，可逆）
  • 补码比原码多表示一个负数：−2⁽ⁿ⁻¹⁾

2. 八/十六进制速记

  • 1 位十六进制 = 4 位二进制；1 位八进制 = 3 位二进制
  • 十六进制转二进制直接查表，不用过十进制
  • 十进制小数转二进制：乘 2 取整，正向排
  • 0.375 = 0.011B（0.375×2=0.75→0，0.75×2=1.5→1，0.5×2=1→1）
A₍₁₆₎ = 1010 F₍₁₆₎ = 1111 7₍₈₎ = 111 5₍₈₎ = 101

3. 移位运算

  • 算术左移 = ×2，右移 = ÷2（符号位不参与移动）
  • 逻辑移位：无符号数，空位一律补 0
  • 循环移位：带进位 CF 或不带进位
  • 左移可能溢出（符号位变化即溢出）；右移是舍去低位，可能损失精度

4. 加减运算与溢出 必考

对补码：A − B = A + (−B)₍补₎ −B 的补码 = B 连同符号位一起取反加 1
  • 单符号位判溢出：最高位进位 ⊕ 次高位进位 = 1 则溢出
  • 双符号位（变形补码）：结果为 01 正溢，10 负溢，00 / 11 正常
  • 双符号位判溢时高符号位才是真正的符号
  • 只有同号相加或异号相减才可能溢出；异号相加绝不溢出

5. IEEE 754 浮点 重难点

单精度 (32 位)：1 阶符 + 8 阶码 + 23 尾数 偏置值 127，真值 = (−1)ˢ × 1.M × 2^(E−127) 双精度 (64 位)：1 + 11（偏置 1023）+ 52
  • 规格化尾数隐含最高位 1，所以尾数实际精度是 24 位（23 存 + 1 隐藏）
  • 阶码全 0：非规格化数（尾数不隐含 1）；阶码全 1：∞（尾数 0）或 NaN（尾数非 0）
  • 单精度规格化数阶码 E 范围 1～254，对应真指数 −126～+127
  • 规格化数最小绝对值 2⁻¹²⁶，最大 2¹²⁸×(1−2⁻²⁴)
  • IEEE 754 尾数用原码表示，阶码用移码（偏置形式）表示

6. 浮点加减五步 必背

① 对阶：小阶向大阶看齐（尾数右移，阶差几位移几位） ② 尾数求和（用补码或原码加减） ③ 规格化：左规 / 右规 ④ 舍入：就近舍入(默认) / 朝零 / 朝 +∞ / 朝 −∞ ⑤ 溢出判断：看阶码是否溢出（尾数溢出可用右规修正）
易错对阶一定用小阶向大阶看齐。反了会丢掉高位有效数字。判溢出只看阶码，尾数溢出不算真溢出。

7. 校验码

  • 奇偶校验：只能检 1 位错，不能纠错，且检不出偶数个错误
  • 海明码：2ᵏ ≥ n + k + 1，能检 2 位错、纠 1 位错
  • 海明码校验位放在 2⁰,2¹,2²… 位置（1,2,4,8…），参与「位号二进制含该位」的所有分组的异或
  • CRC 循环冗余校验：模 2 除法求余数，余数作为校验码

8. 大小端与对齐

  • 大端（Big-Endian）：低地址放高字节；小端相反（x86 是小端）
  • 边界对齐：int（4B）起始地址必须是 4 的倍数，不足则填充
  • 对齐会浪费空间但提高访存效率；不对齐需多次访存拼接
  • C 语言中 int 一般 4B、short 2B、char 1B、long 依平台（64 位 Linux 为 8B）

CHAPTER 03

存储系统

核心 · 12-14 分
本章定位408 计组分值最高、也最容易拉开差距的一章。三种 Cache 映射的地址划分几乎年年考，大题常以「给出主存/Cache 参数 → 求地址格式 → 分析命中情况 → 算平均访问时间」的链条出现。核心心法：一切从「块内地址位数」开始往下推，别记公式结论，记推导顺序。
跨科目本章的「虚拟存储」与 OS 的「内存管理」讲的是同一套机制的两面：这里讲硬件怎么做到（页表基址寄存器、TLB、地址转换、缺页中断的产生），OS 讲软件怎么管（页表由谁维护、缺页怎么处理、页面置换选谁换出）。强烈建议两门课对照着学 —— 计组和 OS 合计 80 分，很大一块就在这里。
考点清单

1. 存储层次与两个「局部性」

CPU → 寄存器 → Cache → 主存 → 辅存 快、小、贵 ←———————→ 慢、大、便宜
  • Cache—主存层：解决速度不匹配，由硬件实现，对所有程序员透明
  • 主存—辅存层：解决容量不足，由硬件 + 操作系统共同实现，对应用程序员透明
  • 局部性原理：时间局部性（刚访问的还会再访问）+ 空间局部性（邻近的会被访问）
  • Cache 命中率 H，平均访问时间 Ta = H·Tc + (1−H)·Tm
  • 口径：上式是「Cache 与主存同时访问」（命中用 Tc，不命中用 Tm）；若题干说「先查 Cache，未命中再访主存」（串行），则 Ta = Tc + (1−H)·Tm。两种口径答案不同，看清题干怎么描述

2. SRAM vs DRAM 必考

3. 存储器扩展

  • 位扩展：增加字长。芯片地址线、片选全部并联，数据线分别接不同位
  • 字扩展：增加字数。数据线并联，用片选信号区分不同芯片
  • 字位同时扩展：先位扩展成组，再字扩展成整体
  • 地址译码有两种：线选法（简单、地址不连续、不能扩展）与译码片选法（用译码器，地址连续）
  • 所需芯片数 = 总容量 ÷ 单片容量

4. Cache 三种映射 重中之重

块内地址位数 = log₂(块大小) 直接映射：Cache行号 = 主存块号 mod Cache总行数 地址 = [ 标记 | 行号 | 块内地址 ] 全相联映射：可放任意行 地址 = [ 标记 | 块内地址 ] 组相联映射（n 路）： Cache组号 = 主存块号 mod Cache组数 地址 = [ 标记 | 组号 | 块内地址 ]
  • 直接映射：硬件最简单、冲突最多；全相联：冲突最少、比较器最贵
  • 组相联是折中，路数 = 每组行数
  • 标记位数 = 主存地址位数 − 行号/组号位数 − 块内地址位数

5. 替换算法与写策略

  • 替换算法：随机 RAND、先进先出 FIFO、近期最少使用 LRU、最不经常使用 LFU
  • 直接映射不需要替换算法（位置唯一）
  • LRU 用计数器实现，命中时被访问行计数器清零、其余加一；比 FIFO 更符合局部性，命中率通常更高
写策略特点
写直达 write-through同时写 Cache 与主存，一致性好、开销大
写回 write-back只写 Cache，需脏位，替换时若脏才写回
写分配写缺失时先调入该块再写
非写分配写缺失时直接写主存，不调入
搭配常见组合：写直达 + 非写分配、写回 + 写分配。

6. 虚拟存储

  • 页式：虚拟地址 = 虚页号 + 页内偏移；页表项含物理页号、有效位、修改位、访问位
  • 页大小固定 → 页内偏移位数固定，虚页号映射到物理页号
  • TLB（快表）：存放常用页表项，SRAM，命中则不必访问主存中的页表
  • 地址转换顺序：VA → TLB（命中直接得物理页号）→ 未命中查页表 → 得物理页号 → 拼偏移得 PA
  • 缺页时触发缺页异常，由操作系统调入页面，若内存满则按置换算法换出
  • 段式按逻辑划分、便于共享保护但会产生外部碎片；段页式结合两者

7. 磁盘与 RAID

  • 磁盘容量 = 面数 × 磁道数/面 × 扇区数/道 × 扇区容量
  • 存取时间 = 寻道时间 + 旋转延迟 + 传输时间
  • 平均旋转延迟 = 转一圈时间 ÷ 2，转一圈 = 60 ÷ 转速(r/min) 秒
  • RAID0 条带化（无冗余、快）、RAID1 镜像（可靠、利用率 50%）、RAID5 分布式奇偶校验（允许坏 1 盘）

8. 计算例题模板

1. 指令格式

指令 = 操作码 OP + 地址码 A1 A2 A3 … 指令字长 = 操作码位数 + Σ 各地址码位数
  • 按地址码个数分：零 / 一 / 二 / 三 / 四地址指令
  • 定长操作码：译码简单，但编码空间浪费
  • 扩展操作码：短码不占用长码的编码空间，靠「短操作码不能是长操作码的前缀」实现——即短码必须留出全 1 等标志位给长码用
  • 指令字长固定时，增加地址码 → 寻址范围变小，二者此消彼长

2. 九种寻址方式与访存次数 必考

寻址方式有效地址 EA访存

3. 基址 vs 变址 高频陷阱

基址寻址变址寻址

面向系统，实现程序浮动用户，实现数组遍历

5. 程序的机器级表示

  • x86 常用寄存器：EAX/EBX/ECX/EDX（通用）、ESP（栈指针）、EBP（帧指针）、EIP（指令指针）
  • call 指令自动压入返回地址（下一条指令地址）并跳转；ret 从栈顶弹出返回地址
  • 栈从高地址向低地址增长，因此「压栈」是 SP 减
  • 局部变量在栈帧内分配，参数传递次序依调用约定（C 语言常见从右向左入栈）
  • 选择结构用条件转移实现；循环结构用条件转移 + 无条件转移回跳实现

6. 扩展操作码编码规则

设操作码基础长度 k 位，每个地址码占 a 位 三地址指令最多 2ᵏ 条 若三地址用了 n₃ 条，剩 (2ᵏ − n₃) 个编码可扩展 二地址可用 = (2ᵏ − n₃) × 2ᵃ 若二地址用了 n₂ 条，剩到一地址的编码再 × 2ᵃ 以此类推……
技巧本质是进制进位：把每一级「没用完的编码」当高位，乘以 2ᵃ 变成下一级的可用空间。做题时画成树状就很清楚。

中央处理器

核心 · 12-14 分

考点清单

1. CPU 内部寄存器 必考

寄存器作用用户可见
PC下一条指令的地址，具自增功能可见
IR当前正在执行的指令不可见
MAR欲访问的主存地址不可见
MDR与主存交换的数据不可见
PSW标志位：ZF/CF/OF/SF可见
ACC累加器，暂存运算结果可见
细节MAR 的位数 = 主存地址线根数；MDR 的位数 = 存储字长。两者都在 CPU 内部。

2. 指令周期四阶段 必背

取指周期 → 间址周期 → 执行周期 → 中断周期 （间址周期只在间接寻址时才有）
取指周期微操作（背下来） (PC) → MAR M(MAR) → MDR (MDR) → IR (PC) + 1 → PC
  • 取指周期结束时，IR 里已经是当前指令
  • 「(PC)+1 → PC」在取指阶段就完成了，这点常考
  • 中断周期由硬件自动完成：关中断、保存断点、送中断服务程序入口

3. 数据通路三种结构

结构特点
单总线所有部件挂一条总线，一次只能传一个数据，微操作需分多步
多总线如双总线、三总线，一条总线传结果、另一条传操作数，可一步完成加法
专用通路寄存器间点对点直连，速度最快，但结构复杂、成本高
关键单总线结构下一次只能有一个部件把数据送上总线，所以「(MDR) + R1 → R1」这种运算必须分两步：先把 MDR 送上总线暂存到 ALU 输入锁存器，再加 R1。这是大题里问「需要几个时钟周期」的根源。

4. 控制器（CU）：功能与结构 必考

  • 控制器是 CPU 的「指挥中心」：只负责发命令，不参与运算、不存放运算数据
  • 核心动作：取指令 → 分析指令（译码）→ 执行指令（按节拍发出微操作命令序列）
「CPU 的五大功能」选择题高频，背五个词： 指令控制 · 操作控制 · 时间控制 · 数据加工 · 中断处理 其中「数据加工」由运算器执行，其余四条都由控制器主导
控制器的五大部件（背下来）： ① PC 程序计数器 —— 给出指令地址 ② IR 指令寄存器 —— 存放当前指令 ③ ID 指令译码器 —— 把操作码翻译成控制信号 ④ 时序系统 —— 产生节拍电位与节拍脉冲 ⑤ 微操作信号发生器 —— 产生全部微操作命令（控制单元 CU 本体）
考点PC、IR 属于控制器——高频判断点。控制器管「指挥」，运算器管「干活」，两者合起来才是 CPU。
时间控制时序系统按三级划分：指令周期 ⊇ 机器周期 ⊇ 时钟周期（节拍）。一个机器周期完成一个基本操作（取指、读一次主存等），含若干节拍；不同指令所需的机器周期数可以不同——这是「各指令执行时间不同」的根源。

5. 硬布线控制器 辨析常考

  • 本质：微操作命令用组合逻辑电路直接「算」出来，又称组合逻辑控制器
  • 三组输入信号决定全部输出：
微操作命令 = f( ① 指令译码信号 , ② 时序信号 , ③ 状态标志 ) ↑ 当前是什么指令　↑ 第几个节拍　↑ ZF / CF 等
  • 设计思路（了解）：列微操作时间表 → 写出各微命令逻辑表达式 → 化简 → 画门电路
  • 特点：速度快（无需读存储器）、电路繁琐不规整、修改扩充极难 → RISC 多采用
硬布线微程序
实现组合逻辑电路控制存储器存微程序
速度快慢（需先读 CM）
修改扩充难，要改电路易，改微程序即可
规整性差好
适用RISCCISC

6. 微程序控制器 · 原理与结构 必考

四层概念链（由大到小，背）： 程序 → 机器指令 → 微程序 → 微指令 → 微命令 · 微命令：最小控制信号，如 PCout、MARin · 微指令：若干微命令的组合，一条可并行发出多个命令 · 微程序：完成一条机器指令的全部微指令序列
  • 核心思想：把「要发哪些命令」代码化写进微指令、存进控制存储器——用「查表」代替「硬连线」
  • 一条机器指令对应一段微程序（一对多）；微指令条数远多于机器指令条数
  • 取指微程序为所有指令公用：所以微程序个数 = 机器指令个数 + 1
  • 控制存储器 CM 在 CPU 内、用 ROM 实现，存放全部微程序
四大部件与工作流程（记成：取 → 存 → 发 → 找下一条）： CMAR 微地址寄存器：指向当前微指令在 CM 中的位置 CM　控制存储器：按 CMAR 取出微指令 → 送入 μIR μIR 微指令寄存器：其中的微命令生效，控制部件完成微操作 微地址形成部件：按 操作码 / 下地址字段 / 增量 算出下一条微地址
易考「机器指令与微指令」的关系是选择题常客：一条机器指令由一段微程序解释执行，取指那条路所有指令都共用。

7. 微指令：格式 · 编码 · 下地址 可出计算

水平型垂直型
并行能力强（一条并发多个微命令）弱（一条做一个微操作）
微指令字长长短（类似机器指令）
微程序条数少（程序短）多（程序长）
补充混合型 = 水平型 + 垂直型的折中，实际机器常用。真题多考水平型与垂直型的两组反比关系（并行能力 ↔ 字长 ↔ 条数）。
编码方式（三种，越往后越省位也越慢）： 直接编码：1 位管 1 个微命令，最快、最长 字段直接编码：互斥的微命令放同一字段、字段内译码 字段间接编码：字段的含义还取决于另一字段（更省位、更慢）
计算题核心公式：字段位数 = ⌈log₂(互斥微命令数 + 1)⌉ 「+1」是给「本段不操作」留的全 0 编码——漏掉必错
  • 下地址形成 3 种：① 操作码 → 入口（取指末，操作码给出执行微程序首地址，这是各指令分岔的路口）② 增量法：(CMAR)+1 顺序执行 ③ 断定法：下地址字段直接给出目标地址
  • 执行方式：串行——执行完本条全部微操作再取下一条；并行——执行本条的同时取下一条（需双端口 CM，硬件更复杂、速度更快）

8. 指令流水线性能 大题常客

流水线周期 Δt = 最长一个阶段的耗时 k 段流水线执行 n 条指令： 总时间 T = (k + n − 1) × Δt 吞吐率 TP = n / T，最大 = 1 / Δt 加速比 S = n·k·Δt / T = nk / (k + n − 1) 效率 E = S / k
  • 流水线不能缩短单条指令的执行时间，只能提高吞吐率
  • 理想情况：第 1 条指令耗时 k·Δt，此后每 Δt 完成一条
  • 流水段数越多，单条指令反而越慢（多了寄存器延迟）

9. 三种冒险与解决 必考

冒险成因解决
结构冒险硬件资源冲突（如同时取指和取数）指令Cache与数据Cache分离、停顿
数据冒险后继指令用到前指令还没写回的结果转发/旁路、停顿、编译调度
控制冒险转移指令改变了下一条指令地址分支预测、延迟槽、停顿
  • 数据冒险三类：RAW（先写后读）最常见、WAR、WAW（后两者只在乱序执行中出现）
  • 转发（旁路）：直接把 ALU 的输出送给下一条指令的 ALU 输入端，不必等写回寄存器
  • load-use 冒险无法只靠转发解决，必须插入一个气泡
  • 分支预测：静态（总预测不跳转/总跳转）、动态（BTB + 历史记录）

10. 多处理器与并行

  • Flynn 分类：SISD、SIMD、MISD、MIMD（多核属于 MIMD）
  • 超标量：一个时钟周期发射多条指令（多套执行部件）
  • 超流水：把流水段进一步细分，一个周期发射多次
  • 超长指令字 VLIW：由编译器把多个操作打包成一条长指令
  • 硬件多线程：细粒度、粗粒度、同时多线程 SMT

按位置分：片内总线 → 系统总线 → 通信总线 系统总线 = 数据总线 + 地址总线 + 控制总线
  • 数据总线：双向。位数决定一次能传多少位数据
  • 地址总线：单向（CPU 发出）。位数决定寻址空间 = 2ⁿ
  • 控制总线：有出有入，传输读/写、中断、时钟等信号
  • 数据总线位数通常与机器字长或存储字长一致
易混「数据总线宽度 = 存储字长」是常见前提。若数据总线 32 位、按字节编址，则一次可传输 4 个地址单元。

2. 总线性能指标 唯一要算的

总线带宽 = 工作频率 × 位宽 ÷ 8 （单位 B/s） 一个总线周期传 W 字节，用 T 秒： 数据传输率 = W / T
例：总线频率 100 MHz，宽度 32 位 带宽 = 100×10⁶ × 32 ÷ 8 = 400 MB/s
  • 总线宽度：能同时传输的数据位数（不是字节）
  • 一个总线周期可能包含多个时钟周期
  • 若「每个总线周期传一个字节，需要 2 个时钟」，则实际带宽要再除以 2

3. 三种集中式仲裁 必考

方式控制线优先级
链式查询最少（3 根）固定，离控制器越近越高
计数器定时查询较多可变（可循环、可编程）
独立请求最多灵活，响应最快
  • 链式查询对电路故障最敏感（某一级坏掉，后面的设备全失效）
  • 独立请求的响应速度最快，但需要的控制线数量随设备数线性增长
  • 分布式仲裁：无中央仲裁器，各设备通过竞争判定

CHAPTER 07

输入/输出系统

中频 · 4-6 分
本章定位概念密度高但深度有限。最高频的两组对比是程序查询 / 中断 / DMA 三种 I/O 方式和中断与 DMA 的差异；最容易失分的是中断隐指令到底做了什么（顺序不能错）和DMA 的三种传送方式。理解主线只有一句：谁在搬数据、CPU 要不要参与。
跨科目本章的四种 I/O 控制方式，在 OS 的「I/O 管理」里会从软件层次再讲一遍：这里讲硬件怎么发起、DMA 怎么抢总线、中断隐指令做了什么，OS 讲设备驱动程序怎么组织请求、中断处理程序进去干什么、磁盘调度怎么排顺序、缓冲怎么配合。两章合起来才是一套完整的 I/O 体系。另外磁盘调度算法在 OS 那边，别在这章找。
考点清单

1. I/O 接口与端口编址

  • 接口中的三类寄存器：数据寄存器（缓冲）、状态寄存器、控制寄存器
  • 状态寄存器中的关键位：就绪/忙、错误、中断允许
  • 统一编址（存储器映射）：I/O 端口占用主存地址空间，用普通访存指令访问，无需专用指令，但占用地址空间
  • 独立编址（I/O 映射）：端口有独立地址空间，需专用 I/O 指令（如 IN/OUT），不占主存空间，但指令功能弱

2. 三种 I/O 方式 必考

程序查询程序中断DMA
谁发起CPU 轮询设备主动设备主动
数据搬运CPUCPUDMA 控制器
CPU 与 I/O串行并行并行
响应时机—指令执行完存取周期结束
CPU 开销极高中（需保护现场）极低
适用简单慢速键盘、打印机磁盘、高速块设备
关键差异中断靠程序搬数据（要执行中断服务程序，有现场保护开销）；DMA 靠硬件搬数据（只需在开始和结束时各打断 CPU 一次）。所以 DMA 优先级高于中断。

3. 中断响应与中断隐指令 必背顺序

中断隐指令（由硬件自动完成，不是程序指令） ① 关中断 ← 防止响应过程被打断 ② 保存断点 ← 把 PC（下一条指令地址）压栈 ③ 取中断服务程序入口 ← 由中断向量提供
  • 响应条件：有中断请求 + 当前指令执行结束 + 允许中断（开中断）
  • 中断判优由硬件排队器或软件查询完成，优先级高的先响应
  • 进入服务程序后要保存现场（通用寄存器、PSW），返回前恢复现场、开中断、执行 iret
  • 多重中断（中断嵌套）的必要条件：在服务程序中提前开中断
  • 中断屏蔽字：1 表示屏蔽（不允许被打断），0 表示开放

4. DMA 传送方式 必考

方式特点
停止 CPU 访存DMA 期间 CPU 完全不访存，结构简单但 CPU 浪费大
周期挪用
（周期窃取）		DMA 每次窃取一个存取周期，CPU 暂停一个周期；最常见
交替访问CPU 与 DMA 轮流各用一个周期，无需申请，效率高但速度受限
  • DMA 控制器内部：地址寄存器（AR）、计数器（WC）、状态/控制逻辑、数据缓冲
  • 传送前 CPU 要预置：主存起始地址、传送字数、传送方向
  • DMA 请求的是总线使用权，中断请求的是 CPU 处理权——这是本质区别
  • DMA 传送结束后用中断方式通知 CPU 做后续处理

5. 通道与外部设备

  • 通道是一种专用处理器，能执行通道程序，独立管理一批 I/O 设备
  • 三种通道类型：字节多路、选择、数组多路
  • 磁盘存取时间 = 寻道 + 旋转延迟 + 传输；平均旋转延迟 = 转一圈时间 ÷ 2
  • 显示器分辨率 × 灰度位数 ÷ 8 = 一帧显存容量；刷新带宽 = 一帧容量 × 帧频

6. 中断全过程速记

设备发中断请求 ↓ 硬件判优，选中优先级最高的 CPU 在指令结束时响应 ↓ 中断隐指令（硬件）：关中断 → 保存断点 → 取入口 执行中断服务程序（软件） ↓ 保存现场 → 处理 → 恢复现场 开中断 → 执行 iret 指令返回
