SECTION 00

四门课全景定位

先看这一节
为什么先看这个408 的四门课不是四条平行线。命题人最喜欢出的题，恰恰落在两门课的交界处——比如「虚拟地址怎么变成物理地址」既考 OS 的页表也考计组的地址转换；「生产者-消费者用信号量怎么写」既考 OS 的同步机制也用数据结构的队列。把交界处想明白了，四门课才是通的。

大题分布
408 的 OS 大题通常出「信号量编程」或「地址转换 + 页面置换」
学这一页之前，你需要先知道

计组 · 存储层次

寄存器 — Cache — 主存 — 辅存。OS 管的是主存与辅存之间的调度（虚拟内存），而 Cache 归硬件管。这个分工要分清。

计组 · 中断

中断隐指令做了三件事：关中断、保存断点、取中断服务程序入口。OS 的中断处理程序就是在它之后接手的。

计组 · 地址

逻辑地址 vs 物理地址的区别，是理解 OS 内存管理的前提。计组讲的是「怎么转」，OS 讲的是「谁来管这张表」。

CHAPTER 01

操作系统概述

基础 · 单选为主
本章定位概念密度大、几乎不考大题，但有两个点会连着后面章节一起考：内核态 / 用户态与特权指令（理解系统调用和中断的前提）、并发与共享（后面所有同步问题的根）。这章快速过，但这两个点要真懂。
考点清单

1. 操作系统的功能

  • 处理机管理：进程控制、同步、通信、调度
  • 存储器管理：内存分配回收、地址映射、内存保护、内存扩充
  • 文件管理：文件存储空间、目录、读写管理、共享保护
  • 设备管理：缓冲、设备分配、设备处理（虚拟设备）
  • 接口：命令接口（联机/脱机）、程序接口（系统调用）、GUI
辨析「编译程序」「汇编程序」属于语言处理程序，是系统软件但不属于 OS。「数据库管理系统」也是系统软件。

2. 四大特征 必考

特征含义
并发宏观上同时、微观上交替。单核同一时刻只有一个程序在运行
共享互斥共享（打印机）、同时共享（磁盘）
虚拟时分复用（CPU）、空分复用（内存）
异步进程走走停停，以不可预知的速度推进
并发 ≠ 并行 并发：单核也能做到（宏观同时、微观交替） 并行：必须多核，同一时刻真正同时执行
关系并发和共享互为存在条件：没有并发就谈不上共享，没有共享并发也无法有效工作。这是常考的一句话。

3. 运行机制：两种状态 核心

用户态（目态）内核态（管态）
能执行的指令只能非特权指令全部指令
典型场景应用程序运行中断处理、系统调用、内核代码
特权指令（只能内核态执行） 开/关中断、I/O 指令、置时钟、清主存、 修改 PSW、设置页表寄存器、加载页表 用户态 → 内核态：唯一途径是 中断 / 异常 / 系统调用 内核态 → 用户态：执行特权指令修改 PSW
易错「陷阱指令（trap）」是用户态主动引发的，属于内部异常，不是特权指令。用户程序可以执行 trap，但 trap 执行后 CPU 就进了内核态。另外，陷入（trap）一词也可以泛指「进入内核态」这件事。

4. 中断与异常

类型来源例子
外中断
（中断）		CPU 外部时钟中断、I/O 完成、键盘
内中断
（异常）		CPU 内部陷入 trap、除零、缺页、非法操作码、地址越界
异常再分三类 故障 fault：可修复，返回当前指令（如缺页） 自陷 trap：有意引发，如系统调用 终止 abort：不可恢复，如除零
与计组的接口这里就是 OS 与计组的交叉点：计组讲中断响应的硬件流程（中断隐指令），OS 讲中断处理程序进去之后做什么。见本页「408 全局定位」。

5. 系统调用 必考

  • 操作系统提供给应用程序的程序接口，是用户态使用内核功能的唯一入口
  • 发生系统调用时 CPU 从用户态切换到内核态，由内核代为完成，再返回用户态
  • 分类：设备管理、文件管理、进程控制、进程通信、内存管理
库函数 vs 系统调用 printf() 是库函数 —— 它内部可能调用 write() 系统调用 但也有一些库函数（如 strcpy）完全不涉及系统调用
考点「哪些操作需要进内核态」是经典送分题：进程切换、文件读写、内存分配、设备操作 需要；算术运算、字符串比较、向变量赋值 不需要。

6. 内核结构

结构特点
宏内核
（大内核）		所有功能都在内核，性能高；但结构复杂、难维护。Linux 属于此类
微内核只留最基本功能（进程管理、中断），其余移到用户态。可靠性高、易扩展；但态切换频繁、性能开销大
分层自底向上分层，便于调试，但效率低
模块化内核模块可动态加载，Linux 支持
一句话微内核的核心思想是机制与策略分离：内核只提供机制（如消息传递），把策略（如具体怎么调度）交给用户态服务进程。

7. 引导与其它

  • 启动流程：CPU 复位 → BIOS 自检 → 读 MBR（主引导记录）→ 引导程序 → 加载 OS 内核
  • OS 的分类：批处理（单道 / 多道）、分时、实时（硬实时 / 软实时）、网络、分布式、嵌入式
  • 分时系统的时间片用完就切换，交互性是它的核心目标
  • 实时系统的首要目标是在截止期限内完成，而不是快
  • 分布式系统各节点无主从之分；网络系统有

CHAPTER 02

进程与线程

高频 · 必有大题
本章定位OS 分值最集中的一块。进程状态转换是选择题的常客，调度算法的计算几乎每年都有一道（求周转时间、带权周转时间、画甘特图）。这两类题都有固定套路，把动画点几遍就熟了。章节末尾的调度对比器可以直接输入数据验算你的手算结果。
考点清单

1. 进程与 PCB 必考

进程 = 程序段 + 数据段 + PCB PCB 是进程存在的唯一标志
  • PCB 内容：进程描述信息（PID/UID）、控制与管理信息、资源分配清单、处理机相关信息（各寄存器值）
  • 进程特征：动态性（最基本）、并发性、独立性、异步性、结构性
  • 进程是资源分配的基本单位，线程是调度的基本单位

2. 进程状态转换 必考

三态：运行 → 就绪 → 阻塞 五态：再加 创建、终止 七态：再加 就绪挂起、阻塞挂起 合法转换 就绪 → 运行：被调度程序选中 运行 → 就绪：时间片用完 / 被抢占 运行 → 阻塞：主动请求资源（如等 I/O）★主动 阻塞 → 就绪：等待的事件发生了 ★被动 创建 → 就绪、运行 → 终止 不可能：阻塞 → 运行（必须经过就绪）
高频陷阱「阻塞→运行」永远错。进程被唤醒后只是回到就绪队列，还要再被调度才能运行。另外「运行→阻塞」是进程主动行为，「运行→就绪」是被动（被剥夺）。

3. 进程控制原语

  • 原语的特点：执行期间不可中断（靠关中断实现）
  • 创建：申请 PCB → 分配资源 → 初始化 PCB → 插入就绪队列
  • 终止：找到 PCB → 若在运行则剥夺 CPU → 释放资源 → 移出队列
  • 阻塞 / 唤醒：成对使用，阻塞是主动的，唤醒是其他进程或中断处理程序做的
  • 进程切换要保存上下文（PC、PSW、通用寄存器）→ 这正是计组的接口点

4. 进程通信

方式特点
共享存储最快，但需要同步互斥；分「基于数据结构」和「基于存储区」
消息传递以格式化消息为单位；直接（指名收/发）或间接（信箱）
管道通信半双工、写入缓冲区、需要同步互斥；本质是共享文件
注意共享存储的两种方式中，基于存储区的共享速度更快、更灵活，因为不受数据结构格式的限制。

5. 线程 必考

线程私有：程序计数器、寄存器、栈、线程 ID 线程共享：地址空间、全局变量、打开的文件、信号处理
用户级线程内核级线程
管理者用户库函数操作系统内核
切换开销小（不用进内核）大（要进内核）
并发能力一个线程阻塞则整个进程阻塞可多线程真正并行
内核是否可见不可见可见
多线程模型多对一（用户级，效率低）、一对一（内核级，开销大）、多对多（前两者折中，最优）。

6. 处理机调度

  • 三级调度：高级（作业调度，外存→内存）、中级（内存调度，对换）、低级（进程调度，最高频）
  • 调度时机：创建、终止、阻塞、唤醒、时间片到、更高优先级进程就绪
  • 不能进行调度的情况：中断处理过程中、进程访问临界资源时、原子操作中
  • 抢占式 vs 非抢占式：抢占式响应快但切换开销大、可能影响一致性
调度评价指标 周转时间 = 完成时间 − 到达时间 带权周转时间 = 周转时间 ÷ 服务时间 （≥1，越小越好） 等待时间 = 周转时间 − 服务时间 响应时间 = 首次响应时刻 − 提交时刻

7. 调度算法 大题

算法特点
FCFS 先来先服务公平、非抢占；对长作业有利、短作业不利
SJF/SPF 短作业优先平均等待时间最短；可能饥饿；分抢占/非抢占
HRRN 高响应比响应比 =(等待+要求服务)/要求服务，折中，不饥饿
优先级分抢占/非抢占；可能饥饿
RR 时间片轮转响应快、适合分时；时间片太小切换开销大
多级反馈队列综合最优，不需预知运行时间；越往下时间片越长、优先级越低
易错「SJF 的平均周转时间最短」是所有算法里严格成立的结论，但「SJF 对短作业有利」≠「对长作业不利到永不执行」——那是饥饿的表述。多级反馈队列里，新进程总是先进入第 1 级队列。

8. 上下文切换

  • 切换内容：保存当前进程的 PC、PSW、通用寄存器到 PCB，再从新进程 PCB 恢复
  • 切换有开销（纯开销，不产生有效工作）
  • 进程切换比线程切换开销大（要换地址空间、刷新 TLB）
  • 同进程内的线程切换不用换页表，所以更快
与计组的接口切换时保存的 PC、PSW、通用寄存器，正是计组第 5 章讲的 CPU 内部寄存器。计组告诉你这些寄存器是什么，OS 告诉你为什么要保存它们。

CHAPTER 03

同步与互斥

大题主战场
本章定位408 操作系统大题出现频率最高的一章。典型形态：给一个场景（几个进程、几类资源、若干约束），要求用信号量写出同步互斥代码。评分看的是信号量设置对不对、PV 顺序对不对。这章别背题，要练「分析约束 → 定信号量初值 → 安排 P/V 位置」这套动作。
考点清单

1. 基本概念与四原则 必考

  • 临界资源：一次只允许一个进程使用的资源（打印机、共享变量、缓冲区）
  • 临界区：访问临界资源的那段代码
  • 进入区 / 临界区 / 退出区 / 剩余区
临界区互斥的四条准则 ① 空闲让进 —— 没人在用就必须能进 ② 忙则等待 —— 有人用就必须等 ③ 有限等待 —— 不能让人无限期等（不能饥饿） ④ 让权等待 —— 进不去要放弃 CPU（不能忙等占着处理机）
记忆前三条是正确性要求，第四条是效率要求。软件方法和硬件方法大多满足前三条，但普遍不满足第四条（都是忙等）。

2. 软件实现四法 理解即可

方法问题
单标志法违背空闲让进（必须交替进入）
双标志·先检查违背忙则等待（双方同时检查、同时进入）
双标志·后检查违背空闲让进与有限等待（可能互相谦让，都进不去）
Peterson 算法正确，但仍是忙等
Peterson 算法的核心（双标志 + 单标志 组合） flag[i] = true; // 我要求进入 turn = j; // 但先让给你 while (flag[j] && turn == j); // 你要是坚持，我就等 ...临界区... flag[i] = false;

3. 硬件实现

  • 中断屏蔽：关中断 → 临界区 → 开中断。单核有效，多核不行
  • TestAndSet（TS）：原子地读出并置真
  • Swap / Exchange：原子地交换两个字的内容
  • 共同缺点：不满足「让权等待」，都是忙等；且可能不满足「有限等待」（TS 可能让某个进程一直抢不到）

4. 信号量机制 核心

整型信号量：只用一个整数，不满足让权等待（忙等） 记录型信号量：整数 + 等待队列，四个条件全满足
记录型信号量的 P / V（原语，不可中断） P(S) / wait(S) V(S) / signal(S) S.value--; S.value++; if (S.value < 0) if (S.value <= 0) block(S.queue); wakeup(S.queue);
读懂这两行S.value 初值代表可用资源数。执行 P 后若 value 小于 0，说明资源不够，自己阻塞；这个负数的绝对值就是等待队列里的进程数。V 操作后有进程在等（value ≤ 0），就唤醒一个。理解这个语义，编程题就不会写反。
顺序陷阱用信号量实现互斥时，P 操作必须在临界区之前、V 操作之后（P 在前）；用信号量实现同步时，V 操作写在前驱动作之后、P 操作写在后继动作之前。P 和 V 谁前谁后写反，就会死锁——这是最常扣分的地方。

5. 信号量的三种用法

用途初值要点
互斥1P、V 夹住临界区，同一进程内成对
同步（前驱）0前操作后 V，后操作前 P
资源计数n初值 = 资源总数
一个信号量既能互斥又能同步吗？ 能，但通常分开设更清晰。 经典生产者-消费者就用了三个： empty（同步，初值 n） full （同步，初值 0） mutex（互斥，初值 1）

6. 经典问题信号量设置 必背

【生产者-消费者】缓冲区大小 n semaphore mutex = 1; // 互斥访问缓冲区 semaphore empty = n; // 空槽位数 semaphore full = 0; // 产品数 生产者： 消费者： P(empty); P(full); P(mutex); P(mutex); ...放入... ...取出... V(mutex); V(mutex); V(full); V(empty); ★ 两个 P 的顺序：必须先 P 资源信号量，再 P 互斥信号量 反了就死锁（拿了锁却等不到槽位，别人也进不来）
【读者-写者】 读优先（可能饿死写者）： semaphore rw = 1; // 读写互斥 semaphore mutex = 1; // 保护 count int count = 0; // 读者数 读者：P(mutex); if(++count==1) P(rw); V(mutex); 读... P(mutex); if(--count==0) V(rw); V(mutex); 写者：P(rw); 写...; V(rw); 写优先：再加一个 w = 1 信号量，读者进门先 P(w)、出门 V(w)
【哲学家进餐】5 人 5 筷，每人需两筷 方案① 最多允许 4 人同时拿筷（设信号量初值 4） 方案② 奇数号先拿左、偶数号先拿右 方案③ 只有左右两支筷都可用时才允许拿（AND 型信号量）

7. 管程

  • 把共享变量 + 对它的操作封装在一起，进程只能通过管程的过程访问
  • 管程内的操作互斥执行（编译器保证，不用手写 PV）
  • 条件变量：wait（阻塞并释放管程）/ signal（唤醒等待者）
  • 与信号量的区别：信号量分散在进程里，管程集中封装；管程的互斥是自动的
对比Java 的 synchronized 就是管程思想。管程 = 类 + 自动加锁。

CHAPTER 04

死锁

中频 · 概念 + 计算
本章定位分值不如前后两章高，但银行家算法是稳定考点（选择题常给一张表让你判断某个请求能否满足）。另外「四个必要条件」和「预防 vs 避免 vs 检测」的区分是必考辨析。
考点清单

1. 死锁的概念与辨析

  • 死锁：多个进程因竞争资源而互相等待，没有外力介入谁都无法推进
  • 饥饿：某个进程长期得不到资源（如 SJF 下的长作业）。饥饿不一定死锁，死锁也不一定饥饿
  • 死循环：程序逻辑问题，不是资源分配问题，OS 不负责
  • 死锁进程至少两个（自己等自己不算死锁）

2. 四个必要条件 必背

① 互斥条件 资源排他使用 ② 不可剥夺 不能强行抢走 ③ 请求并保持 拿着手里的，还要申请新的 ④ 循环等待 存在一个进程—资源的循环等待链
记忆四个条件是必要不充分——四个都满足不一定死锁，但死锁一定四个都满足。所以「破坏任意一个」就能预防死锁。

3. 四种处理策略 必考

策略做法代价
预防破坏四个必要条件之一资源利用率低
避免银行家算法，动态判断本次分配是否安全计算开销大，需预知最大需求
检测允许发生，定期用资源分配图找环路检测开销 + 解除代价
解除剥夺资源 / 撤销进程 / 进程回退可能丢工作
预防的四种破坏方式 破坏互斥 → 很难（有些资源天生互斥） 破坏不可剥夺 → 允许抢，但可能丢工作 破坏请求并保持→ 资源静态分配（一次要够）或释放后再申请 破坏循环等待 → 资源有序分配（编号小的先申请）

4. 银行家算法 高频

四个数据结构（n 个进程，m 类资源） Available[j] ：系统现有可分配的第 j 类资源数 Max[i][j] ：进程 i 对资源 j 的最大需求 Allocation[i][j]：已分配 Need[i][j] = Max − Allocation ：还需要多少 安全性算法（找安全序列） while (存在 Pi 满足 Need[i] ≤ Available) { Available += Allocation[i]; // 它跑完了，资源还回来 把 Pi 加入安全序列; } 若能纳入全部进程 → 安全；否则不安全
易错银行家算法判的是「本次分配后系统是否仍处于安全状态」。请求能不能满足，要先判断 Request ≤ Need 且 Request ≤ Available，再试分配跑一遍安全性算法，安全才真的分配。

5. 资源分配图与检测

  • 图形：圆圈是进程，方框是资源（框内小圆点表示实例数）
  • 申请边 Pi → Rj，分配边 Rj → Pi
  • 每类资源只有一个实例时：图中有环 ⟺ 死锁
  • 每类资源有多个实例时：有环不一定死锁，要化简图
  • 化简方法：找「需求能被满足」的进程，去掉它的所有边（假设它跑完归还资源），反复直到不能再化简。能消去所有边则无死锁
与数据结构接口资源分配图化简本质是图的遍历 / 拓扑消解，和数据结构里的图论是同一套思路。

6. 常见结论速记

  • 系统发生死锁时，一定存在循环等待，但存在循环等待不一定死锁（多实例时）
  • 资源有序分配法破坏了循环等待条件
  • 资源静态分配法破坏了请求并保持条件
  • 银行家算法属于死锁避免，不属于预防
  • 单道批处理系统中不会发生死锁 —— 死锁至少需要两个进程互相等待，而单道同一时刻只有一个程序在运行

CHAPTER 05

内存管理

核心 · 与计组交叉最深
本章定位OS 里与计组结合最紧的一章，也是大题的高产区。两条主线：地址转换（逻辑地址怎么变成物理地址）和页面置换（内存不够了换出谁）。这两件事在计组里叫「虚拟存储」，在 OS 里叫「内存管理」——是同一套机制的两种讲法，建议两本书对照着看。
考点清单

1. 装入与链接

装入方式特点
绝对装入编译时就知道放哪，只适用于单道
静态重定位装入时一次性改地址。运行期间不能移动
动态重定位运行时由重定位寄存器（基址）换算，可移动，是现代 OS 的基础
链接方式 静态链接：装入前全部链接好 装入时动态链接：边装入边链接 运行时动态链接：用到才链接（最灵活，省空间）
保护内存保护常用基址寄存器 + 限长寄存器：地址必须满足 基址 ≤ 物理地址 < 基址+限长，否则越界中断。

2. 连续分配管理 基础

方式碎片
单一连续分配只支持单道
固定分区分配内部碎片（分区内用不完）
动态分区分配外部碎片（空闲区太小用不上）
动态分区的四种分配算法 首次适应 FF ：从低地址找第一个够用的 → 综合最好，性能最优 最佳适应 BF ：找最小的够用分区 → 产生最多外部碎片 最坏适应 WF ：找最大的分区 → 大分区很快被切光 邻近适应 NF ：从上次结束处继续找 → 高地址大块容易被切碎
结论四种算法里 首次适应通常最好（不是最佳适应！名字有迷惑性）。最佳适应的名字指的是"最省空间"，但它会留下大量极小的碎片，反而最差。

3. 基本分页 必考

逻辑地址 = 页号 P + 页内偏移 W 物理地址 = 页框号 F + 页内偏移 W （偏移不变！）
  • 页面大小 = 页框大小，通常 4 KB（偏移占 12 位）
  • 页表：页号 → 页框号，存放在内存中，页表基址寄存器 PTBR 指向它
  • 无 TLB 时访存 2 次：一次查页表、一次取数据
  • 有 TLB 命中时访存 1 次；TLB 未命中仍是 2 次
  • 页表项长度固定，所以「页号」字段可以省略（用索引隐式给出）
与计组的接口TLB 就是「用 SRAM 做的页表缓存」，本质是 Cache 思想：把最常用的页表项放在离 CPU 最近的地方。有效访问时间 EAT 的计算和 Cache 平均访问时间完全同构。

4. 分段与段页式

分页分段
划分依据物理，固定大小逻辑，大小不等
对用户不可见可见
地址一维（一个数）二维（段号+段内偏移）
碎片内部碎片外部碎片
共享保护不易易于（按逻辑模块）
段页式：先分段，段内再分页 地址 = 段号 S + 页号 P + 页内偏移 W 无 TLB 时访存 3 次（查段表 → 查页表 → 取数） 有 TLB 命中时 1 次

5. 请求分页与页表项 必考

请求分页的页表项比基本分页多了几位 页框号 | 状态位(有效位) | 访问位 | 修改位 | 外存地址 状态位：该页是否在内存中（0 → 缺页） 访问位：最近是否被访问过（供置换算法用） 修改位：调入后是否被改过（脏位，决定换出时要不要写回）
  • 缺页时产生缺页中断，属于内中断 / 故障（fault）
  • 缺页中断处理完要重新执行那条引发缺页的指令
  • 一条指令可能产生多次缺页中断（比如指令本身跨页、操作数又跨页）
  • 地址变换顺序：查 TLB → 查页表（未命中）→ 缺页则调页
常考判断缺页中断不是外部中断；缺页中断处理时进程会阻塞（等待 I/O），属于「运行 → 阻塞」的转换。

6. 页面置换算法 大题常客

算法特点
OPT 最佳淘汰未来最久不用的页。缺页最少，但不可实现，只作标尺
FIFO淘汰最早进入的。可能出现 Belady 异常（增加页框反而缺页更多）
LRU淘汰过去最久未用的。性能接近 OPT，但需要硬件支持、开销大
CLOCK环形队列 + 访问位，访问位为 1 则清零并跳过
改进 CLOCK同时看访问位 A 和 修改位 M，优先淘汰 A=0,M=0（不用写回）
改进型 CLOCK 的淘汰顺序（四轮扫描） ① 找 A=0, M=0 → 直接淘汰（最理想，不用写回） ② 找 A=0, M=1 → 淘汰并写回 扫描过程中把经过的 A 置 0 ③ 重复第①轮（此时 M=1 的都变 A=0,M=1） ④ 重复第②轮
只考三种考试真正要手算的通常只有 OPT、FIFO、LRU 三种。CLOCK 系列多考概念和淘汰次序。

7. 抖动与工作集

  • 抖动（颠簸）：刚换出的页马上又要用，频繁缺页。根因是分配的页框数少于局部性所需
  • 工作集：某段时间窗口内实际访问的页面集合。窗口大小 Δ 的选取影响结果
  • 解决办法：按工作集大小分配页框；或挂起部分进程（降低多道程度）
  • 页面大小的影响：太大 → 内部碎片多、调入慢；太小 → 页表大、缺页频繁
页面分配策略三种 固定分配局部置换：页框数固定，只能换自己的页 可变分配全局置换：可从整个系统取空闲页框 可变分配局部置换：页框数可变，但只在自身页之间换（最合理）

文件管理

中频 · 计算为主
本章定位概念多但题型固定。混合索引的最大文件大小计算和位示图的字号位号换算是两个稳定的计算考点，都有固定公式，练熟就是送分。文件分配方式的优劣对比是概念题的常客。
考点清单

1. 文件与目录

  • FCB（文件控制块）：存放文件名、物理位置、逻辑结构、存取权限等，是文件存在的标志
  • 索引结点（inode）：把文件名留在目录项，其余信息全放到索引结点里。这样目录项变小，检索更快
  • 目录结构：单级 → 两级 → 树形 → 无环图
  • 树形目录支持路径名和分类，但不便于共享；无环图解决了共享问题
树形目录的两种路径 绝对路径：从根目录开始 /home/user/a.txt 相对路径：从当前目录开始 ../user/a.txt

2. 文件共享 易混

硬链接软链接
本质多个目录项指向同一个 inode新建一个文件，内容是路径
计数inode 的链接计数 +1不影响原文件计数
删除原文件文件仍可用（计数>0）链接失效
跨文件系统不行可以
记忆硬链接是「同一份东西多个名字」，软链接是「一张写着地址的纸条」。

3. 文件物理结构 必考

方式随机访问问题
连续分配快不利于扩展、外部碎片
隐式链接只能顺序指针占空间、可靠性差
显式链接（FAT）可以（FAT 常驻内存）FAT 表占内存
索引分配快索引块本身占空间
索引分配的三种形式 单级索引：一个索引块 多级索引：索引块指向索引块（文件很大时） 混合索引：直接块 + 一级/二级/三级间接（UNIX 采用）

4. 混合索引计算 高频

典型参数（UNIX 风格） 索引结点含 13 个地址项： 10 个直接地址项 1 个一级间接 1 个二级间接 1 个三级间接 设磁盘块大小 4 KB，每个地址项 4 B 则一个索引块能放 4 KB ÷ 4 B = 1024 个地址项 最大文件大小 直接：10 × 4 KB 一级：1024 × 4 KB 二级：1024² × 4 KB 三级：1024³ × 4 KB 合计 ≈ 4 TB 量级
怎么考通常给一个逻辑块号（如「第 5000 块」），问需要几次访盘。做法：先减掉直接块（10），再减一级间接（1024），看落在哪一级，然后算 1 次索引块 + 1 次数据块（二级间接就是 2 次索引 + 1 次数据）。

5. 空闲空间管理 计算题

方法特点
空闲表法连续分配适用，记录起始块号和块数
空闲链表法空闲盘块链 / 空闲盘区链
位示图法一个二进制位对应一个盘块，1 表示占用、0 表示空闲（或相反，看约定）
成组链接法UNIX 采用。把空闲块分组，每组第一块记录下一组的块号和数量
位示图换算公式（字长为 n 位，编号从 1 开始） 盘块号 b → 字号 = (b−1) ÷ n + 1 位号 = (b−1) mod n + 1 反过来：盘块号 = (字号−1) × n + 位号
易错「从 0 开始编号」和「从 1 开始编号」公式差 1，做题一定先看清题干怎么约定。位示图里 0/1 哪个表示占用，也依题干而定。

6. 文件系统层次

用户接口 ↓ 文件目录系统 ↓ 存取控制验证 ↓ 逻辑文件系统与文件信息缓冲区 ↓ 物理文件系统 ↓ 辅助分配模块 / 设备管理模块
  • 挂载：把一个文件系统接到目录树的某个节点上
  • 虚拟文件系统 VFS：屏蔽不同文件系统的差异，提供统一接口

CHAPTER 07

输入/输出管理

中频 · 与计组交叉
本章定位与计组的 I/O 系统是同一件事的两面：计组讲硬件怎么发起和完成 I/O，OS 讲软件怎么组织和管理它。磁盘调度算法（求移臂总量）是稳定考点，缓冲区的处理时间计算是易错考点。
考点清单

1. I/O 控制方式 与计组重叠

方式CPU 参与度单位
程序查询全程忙等字/字节
程序中断每传一次打断一次字/字节
DMA只在开始结束参与数据块
通道几乎不参与一组数据块
一句话分工计组告诉你 DMA 控制器怎么抢总线，OS 告诉你驱动程序怎么把请求交给它。

2. I/O 软件层次

用户层 I/O 软件（库函数，如 printf） ↓ 设备独立性软件（统一接口、缓冲、分配） ↓ 设备驱动程序（把抽象请求变成设备指令）★厂商写 ↓ 中断处理程序 ↓ 硬件
  • 设备独立性：上层用逻辑设备名，不关心具体是什么设备
  • 设备驱动程序与硬件直接相关，通常由设备厂商提供
  • 设备按传输单位分：块设备（磁盘）、字符设备（键盘）

3. 缓冲技术 易错计算

设：T = 输入一块到缓冲区的时间 C = CPU 处理一块的时间 M = 把缓冲区数据送到用户区的时间 单缓冲：处理一块耗时 = max(C, T) + M 双缓冲：处理一块耗时 = max(C + M, T) 系统处理 n 块的总时间 单缓冲：n × (max(C,T) + M) 双缓冲：n × max(C+M, T) （或再加首块开销）
易错单缓冲里那个 M 是加在 max 外面的，不是里面 —— 因为把数据从缓冲区搬到用户区时，设备和 CPU 都闲着，这段是纯粹串行的开销。这一点很容易记反。
  • 缓冲池（buffer pool）：多个缓冲区统一管理，分空白缓冲队列、输入队列、输出队列
  • 缓冲的作用：缓和 CPU 与 I/O 的速度差、减少中断频率、解决数据粒度不匹配

4. 设备分配与 SPOOLing

  • 设备分配考虑：设备固有属性（独占/共享/虚拟）、分配算法（FCFS / 优先级）、安全性
  • SPOOLing（假脱机）：用磁盘上的输入井/输出井模拟独占设备，把独占设备改造为共享设备
  • 典型例子：打印机。多个进程的打印请求排成队列，由守护进程依次输出
  • SPOOLing 提高了 I/O 速度，把独占设备虚拟成共享设备

5. 磁盘

磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间 寻道时间：磁头移动到目标磁道 ← 主导，占大部分 旋转延迟：扇区转到磁头下 平均旋转延迟 = 转一圈时间 ÷ 2 转一圈时间 = 60 ÷ 转速(r/min) 秒 传输时间 = 读取字节数 ÷ 传输速率
磁盘地址 = 柱面号 + 磁头号 + 扇区号 （柱面号 = 磁道号；磁头号 = 盘面号）
  • 格式化容量比非格式化容量小
  • 坏块处理：扇区备用、扇区滑动
  • 引导块：磁盘第一个扇区（MBR）

6. 磁盘调度算法 必考计算

算法做法特点
FCFS按请求顺序公平，但移臂距离大
SSTF优先最近的平均寻道最短；可能饥饿
SCAN（电梯）单向扫到头再折返不会饥饿；中间磁道更占便宜
C-SCAN单向扫到头后直接回到起点更公平，回程不做服务
LOOKSCAN 的改进：到最远请求就折返不必扫到物理末端
C-LOOKC-SCAN 的改进版到最远请求就返回起点
关键区别SCAN / C-SCAN 扫到磁盘物理末端，LOOK / C-LOOK 扫到最远的那个请求就返回。这是最容易混的一处，看题干问的是哪种。
