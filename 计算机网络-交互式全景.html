计网 × 数据结构算法直接复用，而且是大题

图 → 路由算法
OSPF 用的就是 Dijkstra 最短路径；RIP 是距离向量，本质是 Bellman-Ford 的分布式版本 —— 数据结构第 5 章的两个算法在这里落地
最小生成树 → STP
生成树协议（STP）靠 Prim / Kruskal 的思想在网络里「砍掉环路」，选出唯一一棵无环转发树
队列 → 分组排队
路由器每个输出端口的发送队列、TCP 的接收缓冲区、拥塞控制的滑动窗口，全是队列结构
Trie 树 → 路由表查找
最长前缀匹配如果用朴素顺序比对要 O(n)，换成 Trie（字典树）才能做到与表项数量无关

计网 × 计算机组成原理数据怎么从线上进到内存

中断 → 网卡通知 CPU
网卡收到一个帧、校验通过后发中断，CPU 才知道「有数据来了」。这就是计组第 7 章的中断机制
DMA → 网卡搬数据
大数据包由 DMA 直接写入主存，不占 CPU 的搬运时间；这决定了网卡的吞吐上限
校验码 → CRC
数据链路层的 CRC 与计组的检错纠错编码同源：都是模 2 除法 + 余数判 0
存储层次 → 缓冲区
路由器/交换机的缓冲、TCP 的接收窗口，都是「用存储换时间」；缓冲区大小直接决定丢包率

计网 × 操作系统网络与进程的交界处

socket → 进程通信
套接字是「IP 找到主机、端口找到进程」的落地接口。计网讲端口，OS 讲进程，socket 把两者接上
接收缓冲区 → 生产者消费者
网卡往缓冲区里「生产」，应用进程从里「消费」。这正是 OS 第 3 章 PV 操作的经典场景
协议栈 → 分层处理
OS 里的协议栈是分层的：链路层在中断上下文处理，传输层/应用层在进程上下文处理
端口号 → 进程标识
目标 IP 决定「送到哪台机器」，目标端口决定「交给哪个进程」—— 这是复用/分用的本质

学这一页之前，你需要先知道

二进制与按位运算

子网划分、掩码、IP 分片全是按位与和移位。如果看到 192.168.1.130/26 还不能立刻反应过来「前 26 位是网络号」，先把掩码这块补上。

分层的思想

每一层只负责自己那部分，用下层提供的服务，向上层提供更好的服务。理解这一点，就不会再问「ARP 到底属于哪一层」这种问题。

速率与时延的直觉

「发送时延」和「传播时延」是两件完全不同的事：一个是把比特推上链路，一个是信号在介质里跑。这个区分不清，整章时延计算都会错。

CHAPTER 01

计算机网络体系结构

补充 · 2-3 分

3. 协议的三要素

  • 语法：数据与控制信息的格式（长什么样）
  • 语义：需要发出何种控制信息、完成何种动作、做出何种应答（要干什么）
  • 同步：事件实现顺序的时序关系（先说什么、后说什么）
一句话语法管格式、语义管动作、同步管时序。三者对应「长什么样、干什么、什么时候干」。
注意协议是水平的（同一层的两个实体之间），服务是垂直的（下层向上层提供）。协议 ≠ 服务：协议是「怎么实现」，服务是「对外提供什么」。

4. 速率、带宽、吞吐量

速率（数据率）= 每秒传输的比特数，单位 b/s 1 kb/s = 10³ b/s 1 Mb/s = 10⁶ b/s 带宽 原始含义：信号频带宽度，单位 Hz 计网含义：链路的最高数据率，单位 b/s 吞吐量 = 单位时间实际通过的数据量 始终 ≤ 带宽（受瓶颈链路限制）
最经典的坑网络里的 k = 10³、M = 10⁶（十进制）；而存储容量里的 K = 2¹⁰ = 1024（二进制）。
所以 100 Mb/s 的链路，传 1 MB（2²⁰ B）数据要 约 84 ms，不是 80 ms。

5. 时延的四个组成部分 大题常考

总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延 ① 发送时延（传输时延） = 数据长度(bit) ÷ 发送速率(b/s) ——把全部比特"推上"链路所需的时间 ② 传播时延 = 信道长度(m) ÷ 电磁波传播速率(m/s) ——信号在介质里跑完全程的时间 铜缆/光纤中约 2×10⁸ m/s，自由空间 3×10⁸ m/s ③ 处理时延 + ④ 排队时延：路由器里查表、排队，通常"忽略"
辨析「提高带宽就能变快」是半对：带宽只减小发送时延。传播时延由距离和介质决定，改不了 —— 所以卫星链路的 RTT 天然就大。
推论：长肥管道（高带宽长距离）的瓶颈往往不是带宽，而是 RTT。

6. 时延带宽积与利用率

时延带宽积 = 传播时延 × 带宽 = "链路中能容纳多少比特" = 管道的容积（管道里同时有多少水） 例：带宽 1 Gb/s，单向传播时延 10 ms 时延带宽积 = 10⁹ × 10⁻² = 10⁷ bit = 10 Mbit 利用率（信道利用率）= 有数据通过的时间 ÷ 总时间 当前时延 D = D₀ ÷ (1 − U) → U 趋近 1 时，时延急剧增大（排队爆炸）
怎么记时延带宽积就是「一条管道里装了多少水」 —— 本页动画 02 直接把这个画出来了。
自测速答① 带宽 1 Gb/s、RTT 20 ms 的链路，时延带宽积是多少？（答：10⁹ × 10×10⁻³ = 10⁷ bit = 10 Mbit，注意是单向传播时延）
② 「光纤比铜线快，是因为光纤里光速更快」对不对？（答：错。光纤中光速约 2×10⁸ m/s，比真空慢；光纤的优势是带宽高、损耗小、抗干扰）
③ 同一个数据块，用 100 Mb/s 链路和 1 Gb/s 链路发送，传播时延变不变？（答：不变）

CHAPTER 02

物理层

补充 · 2-3 分
本章定位内容少、但有两个必考公式（奈氏准则、香农公式）和一个必会画法（曼彻斯特编码）。分值只有 2-3 分，却几乎每年至少出一道单选。把公式的口径记准、把波形会画，这章就结束了，不要在这章花多余的时间。
考点清单

1. 奈氏准则（无噪声） 必考

奈奎斯特准则（理想低通信道、无噪声） 极限码元传输速率 = 2W Baud 极限数据传输速率 C = 2W · log₂V (b/s) W = 信道带宽（Hz） V = 一个码元能取多少个离散状态（电平/相位数） 含义：带宽决定了"码元发多快"， 码元状态数决定了"每个码元带多少信息"
怎么推一个码元 = log₂V 个比特。所以 C = 2W × log₂V。
例：W = 3000 Hz、16 种码元 → C = 2×3000×log₂16 = 24000 b/s。

2. 香农公式（有噪声） 必考

香农定理（有噪声、带宽受限） C = W · log₂(1 + S/N) (b/s) S/N = 信号平均功率 ÷ 噪声平均功率（比值，不是 dB！） 信噪比(dB) = 10 · log₁₀(S/N) 含义：噪声给"每个码元能带多少信息"设了上限 —— 这就是为什么不能无限提高 V
最常错公式里用的必须是 S/N 的比值，不是 dB。
题目给「信噪比 30 dB」要先换算：30 = 10·log₁₀(S/N) → S/N = 1000，再代入。
例：W = 3000 Hz、30 dB → C = 3000 × log₂(1001) ≈ 29900 b/s。

3. 两个公式的关系 对比记

奈氏准则香农公式
前提无噪声有噪声
限制来自带宽 + 码元状态数带宽 + 信噪比
能不能靠加电平提速能（V 越大越快）不能（受噪声封顶）
单位b/sb/s
怎么用两个上限取较小的那个作为实际可达速率。
无噪声题用奈氏，有噪声题用香农；题目同时给带宽和信噪比时用香农。

4. 编码与调制

编码规则特点
不归零 NRZ高 = 1、低 = 0（全宽）简单，但无法提取时钟，连续同值时接收方失步
曼彻斯特每个位中间必跳变；本页按 IEEE 802.3：高→低 = 0，低→高 = 1自带时钟（跳变即同步信号），但波特率是数据率的 2 倍
差分曼彻斯特位中间只作时钟；数据看位开始处有无跳变：有跳变 = 0，无跳变 = 1抗干扰更强（看"变没变"比看"是高还是低"可靠）
4B/5B4 位数据映射成 5 位码保证不出现长串 0，配合 NRZI 用（百兆以太网）
口径提醒曼彻斯特的「哪个跳变代表 1」在不同教材里是反的。本页统一采用 IEEE 802.3 约定（高→低 = 0），王道教材同此。做真题时以题目附图为准 —— 只要学会「位中间必跳变、跳变方向携带数据」这个原理，反过来也能读。

5. 传输介质与物理层设备

介质要点
双绞线绞合是为了抵消电磁干扰；UTP 无屏蔽 / STP 有屏蔽；常用于以太网、电话线
同轴电缆抗干扰好、带宽较高，早期以太网 / 有线电视
光纤单模：纤芯细、激光源、损耗小、长距离；多模：纤芯粗、LED 源、距离短。光纤不受电磁干扰
无线无线电、微波（直线传播、需视距）、红外
易错光纤里光速约 2×10⁸ m/s，比真空中的 3×10⁸ 慢。光纤的优势是带宽、损耗、抗干扰，不是「速度快」。
中继器 / 集线器属于物理层，只放大再生信号，不隔离冲突域（集线器所有端口在同一个冲突域里）。

6. 信道复用

方式怎么分典型
频分 FDM按频率分成若干子频带广播、电视、ADSL
时分 TDM按时间片轮流占用电话干线；同步 TDM 有空槽浪费，统计 TDM 按需分配
波分 WDM光纤里按波长复用（FDM 的光学版本）光纤骨干网
码分 CDM各站用相互正交的码片序列，同时同频发送CDMA 移动通信
CDM 计算每站一个码片序列（如 8 位），内积 = 0 表示正交。发 1 就发送自己的码片，发 0 就发送它的反码。接收方用某站的码片去内积：+1 表示该站发了 1、−1 表示发了 0、0 表示没发。
自测速答① 带宽 4 kHz、每个码元 4 种状态，理想无噪声下最高速率？（答：2×4000×log₂4 = 16000 b/s）
② 同样 4 kHz 带宽、信噪比 20 dB，香农上限？（答：S/N = 100 → 4000×log₂101 ≈ 26640 b/s）
③ 曼彻斯特编码的数据率 100 Mb/s，波特率是多少？（答：200 MBaud，因为每个位要两个码元）

CHAPTER 03

数据链路层

主力 · 4-6 分
本章定位第一个「有真东西」的章节。三条主线：怎么把比特流切成帧（组帧）、怎么发现传输错误（CRC）、多个站点怎么共享一条链路（CSMA/CD）。前两条是计算题，第三条是过程题。本章最常考的一题是最小帧长的计算。
跨科目接口与计组：CRC 的模 2 除法 = 计组的检错纠错编码，同一套位运算。
与数据结构：滑动窗口 = 队列 + 环形缓冲；CRC 计算用移位寄存器。
与网络层：链路层只保证「相邻结点之间」正确，端到端的可靠要靠 TCP。
考点清单

1. 数据链路层的三大功能

功能做什么
封装成帧在比特流里划出帧的边界（加帧定界符）
差错控制检错（CRC）+ 纠错；帧丢失/帧序错乱靠序号与确认解决
流量控制别让发送方把接收方冲垮（滑动窗口）
补充「链路」是物理线路，「数据链路」= 物理链路 + 实现通信协议的硬件和软件。链路层管的是相邻结点之间，一跳一跳地负责 —— 端到端的可靠性不归它管。

2. 组帧的三种做法 必考

方法思路缺点
字符计数法帧头放一个「本帧有多少字符」的计数字段计数字段一错，后面全乱套（错位无法恢复）
字节填充法标志字节 FLAG 定界；数据里出现 FLAG/ESC 就在前面插 ESC实现简单，但填充后长度不固定
零比特填充FLAG = 01111110；发送方在数据中每 5 个连续 1 后插一个 0，接收方反向删除最常用（HDLC、PPP），透明传输
核心一句话填充的目的只有一个：让数据里永远不出现和定界符相同的比特模式。这样接收方才不会把数据误当成帧尾。

3. CRC 循环冗余校验 大题常考

设生成多项式 G(x) 的阶为 r（对应 r+1 位二进制串） 发送方： ① 数据后面补 r 个 0 → 被除数 ② 用 G 做模 2 除法（异或，不借位） ③ 余数就是 r 位的 FCS ④ 发出「数据 + FCS」 接收方： 用 G 除「收到的数据 + FCS」 余数 = 0 → 认为无差错 余数 ≠ 0 → 判定有错，丢弃
两个易错点① 模 2 除法是异或，没有借位，不是普通除法。
② CRC 只能检错、不能纠错（FCS 只是余数，不含定位信息）。要纠错得用海明码。

4. 可靠传输的三种协议 对比必记

停止-等待后退 N 帧 GBN选择重传 SR
发送窗口1> 1> 1
接收窗口11> 1
确认方式逐帧确认累积确认逐帧确认
出错时重传那一帧该帧及之后所有帧只重传那一帧
接收方缓存不需要不需要需要（缓存乱序帧）
窗口上限1W ≤ 2ⁿ − 1WT + WR ≤ 2ⁿ
窗口大小怎么来的序号 n 位能表示 2ⁿ 个数。GBN 的接收窗口只有 1，发送窗口若等于 2ⁿ，新旧两组序号会完全重叠，接收方分不清是重传还是新帧 —— 所以必须 ≤ 2ⁿ − 1。
SR 两边都要缓存，加起来不能超过 2ⁿ，所以典型取值是 WT = WR = 2ⁿ⁻¹。

5. CSMA/CD 与最小帧长 必考计算

四点口诀：先听后发、边发边听、冲突停发、随机重发 争用期（冲突窗口）= 2τ τ = 单程传播时延 最坏情况：A 发出的信号快到 B 时，B 才发 —— A 要在 2τ 内还听得到冲突 ★ 最小帧长 = 2τ × 数据率 （以太网取 2τ = 51.2 μs @10 Mb/s 最小帧长 = 51.2 μs × 10 Mb/s = 512 bit = 64 B） 截断二进制指数退避 第 i 次冲突：从 [0, 2^k − 1] 随机取 r，k = min(i, 10) 等待 r × 512 比特时间；冲突 16 次后丢弃并报错
为什么是最小帧长如果帧太短，发送方在冲突信号回来之前就已经发完了，就以为发送成功 —— 冲突检测失效。所以帧必须长到「发完所需时间 ≥ 2τ」。
反过来推：2τ 由链路长度决定，帧长由数据率决定，改一个另一个就要跟着改。

6. 以太网 MAC 帧与交换机

MAC 帧格式（Ethernet V2，单位为字节） 目的MAC(6) | 源MAC(6) | 类型(2) | 数据(46~1500) | FCS(4) 最小帧长 = 64 B（数据段不够 46 B 要填充） 最大帧长 = 1518 B（MTU = 1500 B） 类型字段 > 0x0600 表示上层协议（0x0800 = IP） 长度字段 ≤ 0x0600 时是 802.3 格式

② 查目的地址在交换表里找目的 MAC 对应的端口

交换机隔离冲突域、不隔离广播域；路由器才隔离广播域（划分子网）。

CHAPTER 04

网络层

核心 · 7-10 分
本章定位本章与传输层并列计网的最高分值（各 7-10 分）。网络层解决的是「怎么把分组送到任意一台主机」—— 为此它需要三样东西：编址（IP 地址）、解析（ARP）、选路（路由协议）。考试的三个高频点是：子网划分、分片计算、最长前缀匹配，全是算得出来的题，练熟就是稳分。
跨科目接口与数据结构：OSPF 用 Dijkstra 算最短路径、STP 用最小生成树、路由表查找用 Trie（最长前缀匹配）。
与计组：分组的收发靠DMA 搬运、网卡中断通知 CPU。
考点清单

1. IPv4 数据报首部（20 B 固定部分） 必背

3. 子网掩码与 CIDR 最高频计算

子网掩码：网络号位全 1，主机号位全 0 网络地址 = IP 地址 按位与 子网掩码 广播地址 = 网络地址 | (取反后的掩码) CIDR（无分类编址）：写成 a.b.c.d / n 地址块大小 = 2^(32−n) 可用主机数 = 2^(32−n) − 2 网络前缀 = 前 n 位（必须连续） 例：192.168.1.0/26 块大小 = 2^6 = 64 可用主机 = 64 − 2 = 62 第一个子网：.0 ~ .63（网络 .0、广播 .63） 第二个子网：.64 ~ .127（网络 .64、广播 .127）
路由聚合（构成超网）把几条前缀相同、地址连续的路由合并成一条，取最长公共前缀。
例：192.168.0.0/24 与 192.168.1.0/24 → 合并为 192.168.0.0/23（前 23 位相同）。
聚合是有条件的：合并后的前缀必须能覆盖且仅覆盖这些子网，不能把「别人家的」网段也圈进来。
最长前缀匹配路由表里多条都匹配时，选前缀最长（掩码最长的）那条。因为前缀越长 = 网络越具体 = 越可能是目的地真正所在的网络。
顺序是：先找匹配的，再从中挑最长的，不是看表里谁在前。

4. IP 分片与重组 大题必考

为什么要分片：数据报长度 > 链路 MTU 以太网 MTU = 1500 B 分片时要改的字段（就四个） ① 总长度 → 片的首部 + 该片数据 ② MF → 1 表示后面还有片，最后一片为 0 ③ DF → 置 1 则禁止分片（超 MTU 就丢弃 + 报 ICMP） ④ 片偏移 → 该片数据在原数据中的位置 ÷ 8 计算模板（原始 4000 B，首部 20 B，MTU 1500） 每片数据上限 = 1500 − 20 = 1480 B（且必须是 8 的倍数） 片 1：数据 1480，偏移 0， MF=1，总长 1500 片 2：数据 1480，偏移 185， MF=1，总长 1500 片 3：数据 1020，偏移 370， MF=0，总长 1040

② 每片的数据长度必须是 8 的倍数（因为偏移以 8 B 为单位），最后一片才允许不是。

CHAPTER 05

传输层

核心 · 7-10 分
本章定位本章与网络层并列最高分（各 7-10 分），而且它是全书「过程感」最强的一章。网络层负责把分组送到主机，传输层负责把数据交给具体哪个进程，并且决定「要不要保证可靠」。两条主线：TCP 怎么建立/释放连接（握手挥手）、TCP 怎么控制发送节奏（滑动窗口 + 拥塞控制）。后者的拥塞窗口曲线是大题常客。
跨科目接口与 OS：端口 → 进程标识、接收缓冲区 → 生产者消费者、socket → 系统调用。
与数据结构：滑动窗口本质是环形缓冲 + 队列，超时重传要用定时器管理（最小堆）。
考点清单

1. 端口与复用 / 分用

端口的两个含义 ① 服务端：知名端口，固定分配给某种服务 FTP 21/20、SSH 22、DNS 53、HTTP 80、HTTPS 443、SMTP 25、POP3 110 ② 客户端：临时端口，由系统动态分配（1024 ~ 49151） 复用：多个应用进程共用同一个传输层协议 分用：收到的数据按目的端口号交给对应的进程
一句话抓住IP 地址决定「哪台机器」，端口号决定「哪个进程」。socket = IP + 端口，这就是《计网》与《OS》的交界处。

2. UDP：首部只有 8 字节 必考

UDP 首部（共 8 B，四行每行 2 B） 源端口(2) | 目的端口(2) | 长度(2) | 校验和(2) 长度 = 首部 + 数据的总字节数（最小 8） 校验和：伪首部(12 B) + UDP 首部 + 数据
UDP 的四个特点含义
无连接不需要握手，想发就发
不可靠不确认、不重传、不排序，尽力而为
面向报文应用层给多长就发多长，不合并不拆分
首部开销小8 B，而 TCP 是 20 B
什么时候用 UDP实时性优先、容忍少量丢失的场景：DNS、DHCP、TFTP、RIP、视频直播、游戏。

3. TCP 报文段首部（20 B 固定）

源端口(2) | 目的端口(2) 序号 seq(4) —— 本报文段数据第一个字节的编号 确认号 ack(4) —— 期望收到对方下一个字节的编号 数据偏移(4位) —— 单位 4 B，最小 5（=20 B） 保留(6位) + 六个标志位 窗口(2) —— 接收窗口，告诉对方我还能收多少 校验和(2) | 紧急指针(2) 六个标志位 URG 紧急 ACK 确认 PSH 推送 RST 重置 SYN 同步 FIN 结束
易错确认号 ack = 期望收到的下一个字节序号，所以「收到了 seq=100、长度 20 的段」应答 121，不是 120。
SYN 和 FIN 各消耗一个序号（虽然不带数据），这是握手挥手算序号的关键。

4. 三次握手 / 四次挥手 过程必背

三次握手（SYN 和 ACK 各占一个序号） ① 客户 → 服务：SYN=1, seq=x （不能带数据） ② 服务 → 客户：SYN=1, ACK=1, seq=y, ack=x+1 ③ 客户 → 服务：ACK=1, seq=x+1, ack=y+1 （可带数据） 四次挥手（半关闭：一方先停发，另一方可能还有数据） ① 客户 → 服务：FIN=1, seq=u ② 服务 → 客户：ACK=1, seq=v, ack=u+1 ← 半关闭状态 ③ 服务 → 客户：FIN=1, ACK=1, seq=w, ack=u+1 ④ 客户 → 服务：ACK=1, seq=u+1, ack=w+1 客户进入 TIME_WAIT，等 2MSL 后才真正关闭
为什么是三次、为什么是四次三次：防止「已经失效的连接请求」突然到达服务器 —— 如果只有两次，服务器会白白建立一条连接并一直等数据。第三次握手的作用是让服务器确认「客户端确实收到了我的 SYN+ACK，而且它现在还想连」。
四次：TCP 是全双工。FIN 只表示「我没有数据要发了」，不表示「我也不能收了」。所以 ACK 和 FIN 要分开发（②③之间服务器可能还在发数据）。
TIME_WAIT 等 2MSL 的两个理由① 万一最后的 ACK 丢了，服务器会重传 FIN，客户端还在等就能再答一次；
② 让本次连接产生的所有报文段都从网络中消失，避免干扰下一个相同四元组的新连接。

5. 滑动窗口与流量控制

发送窗口 = min( 接收窗口 rwnd , 拥塞窗口 cwnd ) 接收窗口 rwnd：接收方还剩多少缓存 → 流量控制 拥塞窗口 cwnd：网络当前能承受多少 → 拥塞控制 发送窗口取两者中较小的那个 流量控制的要点 · 接收方通过首部"窗口"字段动态告知 · 窗口为 0 时，发送方启动持续计时器， 到期发一个零窗口探测，避免双方互相死等 · TCP 用累积确认：ack=n 表示 n 之前全部收到
超时重传时间怎么定RTT 是动态估计的：RTTS = (1−α)·RTTS + α·新样本（α 通常 1/8）。
超时时间 RTO = RTTS + 4·RTTD（RTTD 是偏差的加权平均）。
Karn 算法：重传过的报文段不能用它的往返时间来更新 RTTS —— 因为分不清 ACK 是确认哪一次的。

6. 拥塞控制四件套 大题必画

① 慢开始 cwnd 从 1 开始，每收到一个 ACK 就 +1 → 效果：每个 RTT 翻一倍（1, 2, 4, 8 … 指数增长） 到达 ssthresh 后切换 ② 拥塞避免 cwnd ≥ ssthresh 后，每轮 RTT 只 +1（线性增长，"加法增大"） ③ 超时（判为严重拥塞） ssthresh = cwnd ÷ 2 cwnd = 1 ← 回到慢开始 ④ 快重传 + 快恢复（收到 3 个重复 ACK） ssthresh = cwnd ÷ 2 cwnd = ssthresh ← 不回到 1，直接进拥塞避免 （乘法减小 + 加法增大 = AIMD）
最容易错的一句话「一超时 cwnd 就回到 1」和「一收到 3 个重复 ACK 也回到 1」是错的。
超时 → cwnd = 1；3 个重复 ACK → cwnd = ssthresh（新的），直接进拥塞避免。因为快重传说明网络只是轻微拥塞，丢的包还能通过重复 ACK 感知到，不必那么激进地降速。
画图的三个关键点① 慢开始段是指数上升的；② 拥塞避免段是线性上升的；③ 每次拥塞后新 ssthresh 总是「当时 cwnd 的一半」，所以曲线在同一个水平线上反复触及又回落。
自测速答① 客户端发 SYN=1,seq=200，服务器回什么？（答：SYN=1, ACK=1, seq=y（随机）, ack=201）
② cwnd=16 时发生超时，新 ssthresh 和 cwnd 分别是多少？（答：ssthresh = 8，cwnd = 1，回到慢开始）
③ 同样是 cwnd=16，收到 3 个重复 ACK 呢？（答：ssthresh = 8，cwnd = 8，直接进拥塞避免，不回到 1）

应用层

主力 · 4-6 分
本章定位应用层就是「用户能直接看见的那一层」。它没有复杂的算法，考的是协议名 + 端口号 + 工作方式的对应关系，以及 DNS 的查询方式、HTTP 的连接计算。这一章的特点是：概念题多、计算题少，但送分也送得干脆 —— 把下面两张表的对应关系背熟，大部分分就到手了。
考点清单

1. DNS 域名系统 必考

域名结构（从右往左读，越往右级别越高） host.example.com. ↑ ↑ ↑ ↑ 主机 三级域 顶级域 根 四类域名服务器 根域名服务器 —— 全球 13 组，知道所有顶级域的位置 顶级域名服务器 —— .com .cn .org 的管理者 权限域名服务器 —— 具体某个域的权威管理者 本地域名服务器 —— 你所在网络的那个，默认网关附近
查询方式谁问谁对方怎么答
递归查询主机 → 本地域名服务器替它查到底，直接给最终结果
迭代查询本地域名服务器 → 根 / 顶级 / 权限只告诉你「去问下一个」，不代劳
为什么这么设计如果全都用递归，根域名服务器的负载会爆炸。所以「主机到本地服务器」用递归（省客户端的事），「本地服务器到根」用迭代（省根服务器的事）。再加上高速缓存，绝大部分查询根本到不了根。

2. HTTP 超文本传输协议

请求报文 请求行：GET /index.html HTTP/1.1 首部行：Host / User-Agent / Connection: keep-alive … 空行 实体主体（GET 一般没有） 响应报文 状态行：HTTP/1.1 200 OK 首部行：Content-Type / Content-Length / Date … 空行 实体主体（网页内容） 常见状态码 200 OK 成功 301 Moved 永久移动（重定向） 400 Bad 请求报文语法错误 404 Not Found 资源不存在 500 Server 服务器内部错误
连接方式的时延计算非持久连接：每个对象都要新建一次 TCP 连接 → 每个对象花 2 个 RTT（1 个建连 + 1 个请求/响应）。
持久连接（非流水线）：建一次连接，后续每个对象只花 1 个 RTT。
持久连接（流水线）：连着把请求都发出去，时延可以接近于 1 个 RTT 收全部。

4. FTP 与电子邮件

FTP：两个 TCP 连接（带外控制） 控制连接 端口 21 —— 整个会话期间一直保持，传命令 数据连接 端口 20 —— 每传一个文件建一次，传完就关 电子邮件：发和收是两套协议 发送（推）：SMTP，端口 25 用户代理 → 发送方邮件服务器 → 接收方邮件服务器 接收（拉）：POP3 端口 110 / IMAP 端口 143 用户代理 → 自己的邮件服务器 取信 非 ASCII 内容靠 MIME 扩展编码
一句话「SMTP 是推，POP3 是拉」。SMTP 只能传 ASCII，且只负责「送到对方服务器」，取信是另一回事。
POP3 vs IMAPPOP3 默认下载后删除（邮件存在本地，多设备不同步）；IMAP 报文留在服务器上（多设备同步）。
自测速答① 用非持久 HTTP 获取含 1 个 HTML + 5 张图的页面，共需几个 RTT？（答：每个对象 2 RTT，6 × 2 = 12 个 RTT，另有 DNS 解析开销）
② 主机向本地域名服务器发出的是哪种查询？（答：递归查询）
③ FTP 传 3 个文件，一共建立几次数据连接？（答：3 次，每个文件一次）
